# BIM 类别筛选修复 · 2026-10-19

## 复现与原因

修复前，在三维工作台选择 `IfcWall 墙`，选项恢复为“全部类别”，表格首行仍是 Beam。下拉框只使用 `:value`，`change` 处理函数没有保存所选值，因此查询始终使用空类别。楼层下拉框存在同样问题。三维预览原先也没有使用筛选条件。

## 修改

仅修改前端 `BimView.vue` 与 `BimViewer.vue`，重新生成 `frontend/dist`。

- 类别和楼层改为双向绑定，查询使用实际选择，变更后回到第一页。
- 已加载网格按当前类别及所属楼层过滤，同步更新三维显示和可见数量。
- 筛选为空时清除旧模型、选择框和证据标记，显示明确的空预览提示；不将未加载几何理解为模型没有构件。
- 按需加载的几何加入当前网格集合后自动参与筛选；恢复全部类别可显示所有已加载几何。

不新增全量模型自动加载，不修改后端、Case 流程或证据策略。

## 验证结果

- `npm run build` 通过，包含 Vue TypeScript 检查与 Vite 生产构建。
- 实际浏览器：墙预览 31 个，索引 580 条；楼板预览 4 个，索引 41 条；各列表当前页均只包含对应类别。
- 覆盖层：预览与索引均为 0，空状态可见。
- `IfcBuildingElementProxy`：索引 411 条；选择首个构件并按需加载，预览从 0 变为 1，总已加载数从 35 变为 36。
- 恢复全部类别：可见 36 个已加载对象，索引恢复到 1,247 条。
- 切换 04 层：不继续显示 05 层几何，并展示当前只建立了 05 层索引的范围说明。

浏览器断言记录见同目录 `browser-filter-results.json`，修复截图在 `04_演示与截图/BIM类别筛选修复_20261019`。
