# Agent 框架 2.0 开发与验收

日期：2026-10-19。目标是在原平台内落地证据驱动、约束规划、人工授权与可恢复执行；保持确定性规则、既有审核整改闭环和本机演示体验。

## 本轮变更

- 后端新增 `assurance.py`、`durable.py`、`access.py`：类型化工具契约、计划子任务、输入与文件哈希、证据关系、结构化校核、定向补证、持久任务/检查点、人工中断、角色和项目权限。
- `agent.py` 保留原专业计算与模型职责，增加补证与校核节点。资料不足时暂停风险摘要及控制措施的模型生成，保留未知项，等待人工。
- `services.py` 增加结果幂等、旧输入阻断、审核输入绑定、复核输入哈希，以及同事务生命周期 outbox。正常业务接口继续负责批准、实施和关闭。
- 项目经验只作已复核案例索引，最多 3 条；不作为当前证据。只读结果复用限同案且相关输入一致，不缓存风险通过、审批或复核。
- 前端 AI 下方新增可折叠“检查计划与依据”，展示计划、证据/单位/来源、规范页码/版本、校核与待补资料；处理按钮进入已有资料区域。可恢复失败与取消操作在面板内提供。
- 保留白色 BIM 背景、19 层参观、L05 安全检查、P1/P2、流式输出、EV-002/EV-010 内置整改资料及 Word 下载。
- 默认本机免登录；令牌角色模式可选。本轮未更改 `.env`、未生成操作员令牌、未变更公开站点。

## 真实网页完整闭环

案例：[CASE-20261019-1A75FF](http://127.0.0.1:8003/cases/CASE-20261019-1A75FF)，运行 `RUN-20261019-FFA906`。

1. 首页选择 EV-003 栏杆偏低，输入 L05 临边与人员暴露总体任务，发起检查。
2. DeepSeek 完成 task_plan、risk_summary、control_draft 共 3 次调用，合计 7,701 tokens。程序比较 1.0 m 与 1.2 m 阈值，结果为风险候选，进入人工审核。
3. 查看检查计划、8 条模拟观察、3 条规范的页码与版本，以及约束校核。结构化依据关系 67 条。
4. 网页人工批准当前措施；选择原有 EV-010 栏杆加高与防护复核资料，09:20 完成整改，09:30 资料，09:40 人工执行复核。
5. 复核按批准参数、证据匹配和时序检查通过，案例 closed、版本 7；生命周期检查点显示 complete。

本例使用明确标注的演示观察与几何派生示意图，不是现场施工合格验证。本轮沿用 Qwen 上传/确认流程，未为本例重复调用图像模型。

案例、完整运行与流程检查点的 JSON 均保存在本目录。Word API 下载为有效 `.docx`，已渲染并检查 6 页：表格续页有重复表头、无文字溢出或缺字，末页为适用边界说明的延续；源 Word 排版代码本轮未修改。渲染中间文件在 `word-render/`，用于内部验收。

## 缺资料与恢复

案例：[CASE-20261019-29D33A](http://127.0.0.1:8003/cases/CASE-20261019-29D33A)，运行 `RUN-20261019-BDF2EF`。

使用 EV-004 缺字段资料。保留开发过程中契约兼容问题及热重载前一次续跑失败的轨迹；最终从保存的节点续跑成功，未重复 BIM 节点或 DeepSeek 规划。最终记录 3 次领取、2 次恢复。

本轮 task_plan 仅调用 1 次 DeepSeek，1,501 tokens；没有 risk_summary / control_draft 调用。程序列出防护状态、人员在场、固定、连续和 PPE 共 5 项缺口，案例停在 needs_evidence、无措施；批准请求返回 409（`gap-approval-blocked.json`）。网页点击“处理”进入现场资料，可继续补证或上传。

恢复可靠性另有两个隔离子进程强制退出测试：完成 BIM 后退出，恢复不重复 BIM；业务提交后、运行成功标记前退出，恢复不重复提交 Case 版本或业务事件。不能据此承诺收费外部接口绝不重试，也不能宣称任意断电硬件故障已经验证。
