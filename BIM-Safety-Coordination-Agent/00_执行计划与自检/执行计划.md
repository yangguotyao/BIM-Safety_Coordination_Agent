## 1. 目标、边界与交付定义

### 1.1 案例定位

案例名称：**BIM-Safety Coordination Agent（IM-Safety Coordination Agent）**。

核心主张不是“让 LLM 操作 BIM”，而是：

> 让 LLM Agent 把施工安全任务、BIM 空间信息、施工进度和安全规范连接起来，形成可审核、可实施、可复核、可重新打开的 Safety Case。

网站面向文献综述中的案例展示，必须同时讲清三件事：

1. **工程对象真实**：三维构件来自 S1 的真实 IFC 几何，GUID、楼层、构件类别和空间坐标可追溯。
2. **Agent 过程真实**：六类职责节点、工具调用、状态迁移、人工审核和数据库持久化真实执行，不用动画伪造。
3. **证据边界诚实**：现场观察、施工活动、防护状态和 2.5 m 坠落高度是模拟输入；页面持续标注“演示示意图 / 非现场照片 / 演示策略”。

### 1.2 必须交付

- 可运行的 Vue 3 + TypeScript + Vite + Three.js 前端。
- 可运行的 FastAPI + Pydantic + LangGraph + SQLite 后端。
- 真实 S1 IFC 的 35 对象区域预览、构件查询、点选、GUID 映射和按需网格提取。
- 完整 Safety Case 闭环：新建 → 分析 → 补证 → 人工审核 → 实施 → 复核 → 关闭 / 重开。
- Agent 实际调用记录：节点、工具、输入摘要、结构化输出、状态、错误和简短决策依据。
- 规范知识库：仅索引 7 条 active 人工核对释义，排除 retired；保留标准号、条款、PDF 页码和原文入口。
- 12 项验收场景的可重复执行界面与结果记录。
- 资料整合包、执行计划、自检记录、演示手册、实际测试报告、必要截图。
- macOS/Linux `start.sh`、Windows `start.ps1`、`.env.example`、README、依赖锁定文件。

### 1.3 明确不做

- 不做真实事故概率预测，不把“高/中/低”写成校准风险值。
- 不宣称 S1 板边就是真实建筑临空面，不宣称 17.3 m 世界高程就是坠落高度。
- 不宣称识别出真实 MEP 安装任务、真实洞口或真实 4D 计划。
- 不接入收费模型，不提交密钥，不连接参考项目的生产数据库。
- 不复制参考仓库代码；参考站点只用于交互形式参考。
- 不把 OCR 全文当已核验规范，不把演示证据当现场照片。
- 不替代施工单位、安全员或监管机构的真实审批。

### 2.4 角色口径统一

聊天截图目录中出现 `bim_agent.py`，原方案角色表出现 6 类职责，任务书要求 Coordinator、Knowledge、Inspection、Risk、Intervention、Verification 六类节点。执行口径：

- **六类职责节点**全部保留并在 Agent 页面可见。
- **BIM 不作为独立 LLM Agent**，而封装为 `bim_query`、`spatial_check`、`schedule_query` 三个确定性工具；这样避免“LLM 自己算几何”。
- 截图中的 `bim_agent.py` 对应到“BIM 工具与三维工作台”，在界面和文档中解释该映射，不伪造第七个 LLM 节点。

## 3. 技术架构

### 3.1 总体结构

```text
浏览器
  Vue 3 + TypeScript + Vite + Three.js
        │  /api  JSON / 文件
        ▼
FastAPI（127.0.0.1:8000）
  ├─ REST API + 静态前端托管（生产构建）
  ├─ Pydantic 请求/响应校验
  ├─ LangGraph 六节点工作流
  ├─ SQLite（WAL、外键、事务、FTS5 二元组）
  ├─ IfcOpenShell 懒加载 + 网格缓存
  └─ runtime/ 数据库、上传件、导出件
        │
        ▼
资料包 01_资料与依据（只读原件）
```

### 3.2 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite | 任务书指定；组件化、构建快 |
| 三维 | Three.js + OrbitControls | 直接消费真实三角网格；不依赖 Revit |
| 样式 | 原生 CSS 设计系统 | 避免重型 UI 库，控制视觉一致性 |
| 图标 | lucide-vue-next | 轻量、统一 |
| 后端 | FastAPI + Pydantic v2 | 任务书指定；自动校验与 OpenAPI |
| Agent | LangGraph | 任务书指定；显式节点与状态 |
| 存储 | SQLite + FTS5 | 零外部服务；事务与持久化 |
| BIM | IfcOpenShell 0.9.0.post1 | 真实 IFC 解析与按需几何 |
| 测试 | pytest + httpx + 浏览器实测 | API、状态机、页面交互三层 |

### 3.3 运行形态

- 开发：前端 Vite `127.0.0.1:5173`，后端 `127.0.0.1:8000`，Vite 代理 `/api`。
- 交付：`npm run build` 后由 FastAPI 托管 `frontend/dist`，统一从 `http://127.0.0.1:8000` 访问。
- 数据库、上传、导出均在 `runtime/`；重置只影响该目录。
- 默认 `DEMO_MODE=true`；无密钥可完成全部 12 项验收。
- 真实模型模式通过 `MODEL_BASE_URL / MODEL_API_KEY / MODEL_NAME` 显式开启；配置不完整返回可操作错误，不静默降级。

## 5. 网站信息架构与交互

### 5.1 导航

1. **总览**：案例定位、实时指标、六节点流程、最近案例、验收摘要、边界声明。
2. **BIM 模型**：三维工作台、楼层/类别/关键字筛选、构件表、属性面板、证据定位。
3. **安全案例**：案例列表 + 详情；状态机、证据、Finding、Control、审核、实施、复核、事件。
4. **Agent 工作流**：六节点图、最近 run、逐节点 trace、工具输入输出、失败与重试。
5. **规范知识库**：search、active/retired 过滤、条文释义、PDF 页码、原文打开。
6. **证据库**：12 张演示证据、观察字段、时间/区域/版本匹配、定位 BIM 构件。
7. **验收实验室**：12 项一键执行/全部执行、期望 vs 实际、通过/失败、重置夹具。
8. **方案与边界**：原始方案对应关系、数据事实、缺口、Agent 设计、引用说明。

### 5.2 关键交互（必须真实调用后端）

| 交互 | 后端行为 | 持久化 |
|---|---|---|
| 新建案例 | 校验 task/zone/model/GUID，写 cases + event | 是 |
| 分析 | 创建 run，LangGraph 执行，写 agent_events | 是 |
| 轮询 run | 返回 queued/running/succeeded/failed + trace | 是 |
| 审核 | approve/reject/modify，检查版本 | 是 |
| 实施 | 仅 approved，记录 owner/time/comment | 是 |
| 提交证据 | 选择包内证据或上传 PNG/JPG/PDF，<=20MB | 是 |
| 复核 | 时间/区域/构件/规则/防护检查，人工确认 | 是 |
| 重开 | 保留 closed 事件，新增 reopened | 是 |
| 导出 | JSON / Markdown，含来源与数据性质 | 文件 |
| 重置 | 二次确认，只重建 runtime 演示库 | 是 |

### 5.3 视觉方向

- 深色“工程控制台”基调：深海军蓝背景、青绿色主操作、琥珀色风险、红色仅用于风险候选。
- 信息密度高但不拥挤；表格、状态徽章、时间线、检查项清晰。
- 三维区占主视觉；右侧属性/证据联动；底部构件表可筛选。
- 所有模拟内容带 `模拟` / `演示` 徽章；所有规范内容带 `条文释义` 标签。
- 桌面优先（1440×900），兼顾 1280 宽；移动端只保证可读与可操作，不承诺完整三维体验。

## 6. 数据模型、接口与状态机

### 6.1 SQLite 表

`projects, models, storeys, elements, zones, tasks, evidence, rules, rules_fts, cases, case_events, runs, agent_events, uploads, acceptance_results, settings`

- 外键开启；案例更新与事件写入同事务。
- `cases.version` 乐观锁；`expected_case_version` 不匹配返回 409。
- 状态冲突 409；字段/跨项目引用 422；对象不存在 404。
- 所有时间 ISO8601 带时区；长度米。

### 6.2 状态机

```text
draft ──analyze──> analyzing ──┬─> pending_review ──approve──> approved
                               ├─> needs_evidence ──补证/重析──> analyzing
                               └─> rejected（审核拒绝）
approved ──implementation──> rectifying ──after evidence──> pending_verification
pending_verification ──verify(pass)──> closed
pending_verification ──verify(fail)──> reopened
closed ──reopen(条件变化)──> reopened
reopened ──analyze──> analyzing
```

- 无风险且无控制措施的案例，审核通过后可直接关闭，`verification=null`，事件写明“已检查项未发现问题，无需整改”。
- 未经批准不得进入 rectifying；未提交实施后证据和人工确认不得 closed。
- 旧版本审批不得覆盖新控制方案；修改控制措施必须新增版本并重新审核。

### 6.4 工具合同

所有工具返回：

```json
{
  "ok": true,
  "data": {},
  "provenance": "real_source|derived_geometry|simulated|mixed",
  "model_version": "4075c44a6e47",
  "units": "m",
  "method": "…",
  "evidence_ids": [],
  "rule_ids": [],
  "uncertainties": [],
  "error": null
}
```

- `bim_query`：GUID/类别/楼层查询；GUID 不存在返回 `ok=false`。
- `spatial_check`：点到已标注板边线的二维欧氏距离；AABB 只用于候选筛选。
- `schedule_query`：检查时刻是否落在任务时间窗。
- `rule_retrieval`：active 条款 top-3；retired 永不出现在结果。
- `evidence_check`：项目/模型版本/区域/时间窗/字段完整性。
- `risk_assessment`：结构化判定，不产出未经执行的几何数值。
- `verification_check`：实施后证据的时间、区域、构件、检查项与人工确认。

## 7. Agent 工作流

| 顺序 | 节点 | 责任 | 调用工具 | 写入 trace |
|---|---|---|---|---|
| 1 | Safety Coordinator · 准备 | 校验案例、模型版本、区域、时刻 | 无 | 输入摘要、状态判断 |
| 2 | BIM Context | 构件属性、楼层、空间关系 | `bim_query` | GUID、类别、bbox、单位 |
| 3 | Schedule | 当前活动与时间窗 | `schedule_query` | 活动、起止、provenance |
| 4 | Inspection | 证据匹配与结构化观察 | `evidence_check` | 匹配结果、缺失字段、不确定性 |
| 5 | Knowledge | 检索当前有效条款 | `rule_retrieval` | query、top-k、rule_ids、PDF 页 |
| 6 | Risk | 综合几何/活动/证据/规则 | `risk_assessment` | 检查项、result、风险候选 |
| 7 | LLM 归纳 | 只在证据/规则/工具结果内生成摘要；演示模式用确定性模板 | 无（演示）/ OpenAI-compatible（真实） | summary、basis、uncertainties |
| 8 | Intervention | 生成可审核措施 | 模板 + 规则 | 措施、责任人、验证要求、版本 |
| 9 | Verification · 计划 | 明确关闭案例所需的实施后证据 | `verification_plan` | 复核要求、边界 |
| 10 | Coordinator · 收口 | 决定 pending_review / needs_evidence | 无 | 状态、下一步、失败信息 |

- 关键工具失败最多重试 1 次；仍失败则 run=`failed`，案例标记“分析不完整”，不自动判无风险。
- 演示模式的自然语言归纳采用确定性模板，界面标注“演示模型输出”。
- 真实模式只允许在已检索规则、已执行工具结果、已标注证据内归纳；Pydantic 校验输出白名单（GUID/rule_id/evidence_id）。
- trace 展示实际节点、工具输入摘要、返回数据、状态、错误、决策依据；不展示内部思维过程。

## 12. 完成定义（DoD）

同时满足以下条件才算交付：

1. `scripts/start.sh` 可从干净终端启动，输出实际 URL。
2. 前端构建成功，`http://127.0.0.1:8000` 可打开；无控制台阻断错误。
3. 三维区可旋转、缩放、点选构件、筛选、定位证据。
4. 新建 → 分析 → 审核 → 实施 → 复核 → 关闭 全流程可走通；刷新后状态保留。
5. 12 项验收全部返回期望结果，报告含实际响应摘要和时间戳。
6. 无密钥启动、重启持久化、无效真实模型配置三项附加测试通过。
7. 资料整合包、执行计划、自检记录、测试报告、演示手册齐全。
8. 所有模拟/真实边界在网站与文档中可检索到。
