# BIM 施工安全协同 Agent · 2.0 可用版

2026-10-19：沿用 Vue 3 + FastAPI + LangGraph 与真实 DeepSeek / Qwen 接入，保留 P1 三维标注和 P2 时空冲突、现场文本澄清。首页改为模型浏览与任务入口并列，支持 19 个模型楼层浏览；完整安全检查仍以 05 层板边为范围。AI 分析位于模型上方并实时输出，整改与证据合并提交，报告默认下载 Word。

2.0 在这条业务流程内增加检查计划、证据依据与约束校核；缺资料时列出定向补证清单，暂停风险文字和措施生成。模型负责理解与文字候选，距离、时段、阈值、状态流转和最终复核仍由程序执行，批准与复核确认仍由人工操作。

## 启动

双击本目录 `Start-Demo.cmd`，访问 http://127.0.0.1:8003/ 。Windows 启动脚本默认端口为 8003，已验证可复用当前新版服务。此前服务保留，请使用新入口；无需重置数据库。

项目独立环境保持 Python 3.11、FastAPI 0.141.1、Uvicorn 0.52.4、Pydantic Settings 2.15.0、Node 22、Vue 3.5.18、Vite 7.1.3。前端构建产物已更新。

新增依赖 `langgraph-checkpoint-sqlite==3.0.3` 已装入当前环境并锁定；LangGraph 仍为 1.0.10。启动时会校验检查点依赖，迁移到另一台电脑时运行 `02_网站源码/scripts/setup.ps1` 安装锁定依赖。默认仅本机访问，无新增登录步骤；角色权限模式的配置见下文。

配置优先读取外层 `D:\BIM-Safety_Coordination_Agent\.env`；仅在该文件不存在时读取 `02_网站源码/backend/.env`。外层配置现保留 DeepSeek、Qwen、超时与思考模式开关，`DEMO_MODE=false`。DeepSeek 使用 `deepseek-v4-flash`，图像使用 `qwen3.7-plus`。修改配置后需重新启动服务。密钥不会通过健康接口或调用记录返回。

## 推荐演示路线

2.0 框架快速查看：[已完成的真实模型闭环](http://127.0.0.1:8003/cases/CASE-20261019-1A75FF)，进入“协同工作台”并展开 AI 下方“检查计划与依据”，可切换检查计划、证据依据和约束校核。[定向补证与恢复案例](http://127.0.0.1:8003/cases/CASE-20261019-29D33A) 显示 5 项缺口且不能批准；点击“处理”进入对应资料。原 `CASE-20261019-1DAC34` 保持原有待整改状态和版本 7。

新版流程快速查看：[从首页发起并完成整改复核的 Case](http://127.0.0.1:8003/cases/CASE-20261019-375C02)。P1 / P2 扩展示例：[时空冲突与文本澄清闭环](http://127.0.0.1:8003/cases/CASE-20261019-4CF647)，以及[可继续整改的计划调整 Case](http://127.0.0.1:8003/cases/CASE-20261019-3914FF)。

1. 首页通过“浏览楼层”参观整栋或单层模型。整栋或 05 层视图下可在“发起检查任务”输入总体任务，添加现场照片，或展开“检查资料与时刻”选择演示资料，再点击“发起检查”。其他楼层仅支持模型浏览。未提供资料也能发起任务，Agent 会停在待补资料，不能直接批准。
2. 自动进入 05 层检查工作台，模型上方显示 AI 分析及实际工具进度。实时文字来自真实 DeepSeek 流；最终结论须通过引用与参数校核。若上传了新照片，在“现场资料”核对 Qwen 候选，确认来源与观察，再重新分析。高度等米制参数须人工录入，未知项保留未知。
3. 需要精确选择构件时，从首页“查看05层构件”进入局部模型，筛选类别、搜索 GUID、选择楼板并“检查选中楼板”。检查页可直接点选边线、标注或拖动人员点，查看距边线距离。同案工作台也可通过“范围与人员”调整并重新分析。
4. 在“协同工作台 → 施工活动”编制至少两项活动，录入工种、责任主体、时间和作业空间体，点击“保存并校核”。同时同地才触发时空冲突。点击冲突定位三维范围；点风险项关联对应构件、证据和条款。
5. 在“现场文本”录入带来源和时间的巡检记录，点击“提取文本候选”，或由 Agent 分析时提取。核对原文段落；若与确认观察存在差异，填写依据并“确认澄清”，然后重新分析。文字不会自动改写照片确认值。
6. 在“审核与措施”批准当前版本。若仍有计划冲突，先调整活动时间或空间并填写依据，保存后重新校核。审批后的活动 ID、工种和责任主体锁定，原计划版本保留。进入“隐患整改”，填写责任人、整改完成时刻与说明。可直接“选择演示整改资料”：防护缺失推荐 EV-002，栏杆偏低推荐 EV-010；页面显示原始示意图、模拟观察和前后对照。也可“上传新资料”，然后一次“提交整改与证据”。内置资料保留原始 09:30 时间，常规演示沿用 09:20 整改完成、09:40 复核；晚于资料时刻的整改不能使用这份旧资料。
7. 内置资料直接使用明确标注的模拟观察；上传的新图片自动调用 Qwen 生成候选，须核对并保存人工观察。随后在同一区域填写复核时刻，点击一次“确认资料并执行复核”。无需再到旁边选择同一张证据，也无需额外勾选重复确认。自定义验收要求仍需确认；时间、GUID、批准版本及计划冲突继续由后端校核。通过后关闭 Case，点击“导出检查报告”下载 `.docx`。隐患与资料的对应关系见 `03_测试与验收/内置整改资料_20261019/资料对应与验收.md`。

“Agent 记录”显示实际工具轨迹、模型、耗时与 token 用量。Word 报告包含范围、检查依据、整改、复核、证据来源、计划版本、原文及澄清记录；“更多”保留 JSON 导出，旧 Markdown API 兼容。模型调用失败会保留资料并显示失败状态，不自动批准或判定无风险。

## 数据与能力边界

真实数据：S1 IFC、构件 GUID、楼层、米制网格、所选构件包围盒、网格顶面候选边线，以及公开 S1 原始照片。照片与本次所选楼板的映射为演示人工关联，未证明拍摄位置精确对应该 GUID，也未证明两张照片是真实整改前后记录。

演示输入：施工活动与作业窗口、人员点、临空性质、现场防护高度与坠落高度、审批身份和整改实施。图像模型只提供候选，不从图片推断米制高度或锚固强度；人工确认记录保留来源、说明和版本。历史照片使用受控案例时钟，不把文件名时间解释为已核实相机时区。

当前仍是以 05 层楼板板边为中心的可控安全检查系统。整栋总览来自当前 IFC 全部 16,372 个有表示构件，按楼层和类别合并为 154 个批次；19 个模型楼层均有几何，含基础层、首层和屋面，浏览时只筛选同一份约 18.1 MB GLB，无额外 IFC 解析。板边局部预览为 35 个网格，其他构件按 GUID 加载。全项目拓扑、自动临空面识别和真实 4D 计划仍待补齐。规范按检查时刻筛选生效日期，本轮没有重新审定条文释义。2019 年验收案例不使用 2023 年才生效的条款。

人工批准、措施版本、实施时间、证据 GUID 和复核参数均有校核。旧证据排序与重开后的既有证据选择策略按此前约定保留。没有增加施工方案审查业务，也没有替换公开网站。

同一 Case 的近期消息保存在 SQLite，每次规划最多读取 6 条、正文累计不超过 6,000 UTF-8 字节；BIM、规则、证据通过工具按需读取，模型不接收整个 IFC。业务状态保存在 `02_网站源码/backend/runtime/app.db`。

2.0 工作记忆保存计划与缺口，Case 记忆保留消息及批准版本，项目经验仅索引最多 3 条已复核的相关演示案例，作为流程参考，不作为当前证据。图检查点保存在 `runtime/agent-checkpoints.sqlite`，与业务数据库分开。后台 worker 使用持久任务、18 秒租约与心跳；重启后可恢复已提交节点。未完成的外部调用可能重试。输入变化时拒绝旧运行；可恢复故障可展开“检查计划与依据”选择“从中断节点继续”。当前调用返回后才响应取消。

新审查器校核结构化事实、单位、引用、规范版本与工程阈值，不证明任意自然语言句子的正确性。完整安全场景仍限于 L05，真实现场验证及论文大模型对照实验尚未完成。

## 可选角色权限模式

默认 `ACCESS_MODE=local_demo` 仅允许本机回环访问，保留当前演示体验。若需要按角色试用，在外层 `.env` 设置 `ACCESS_MODE=token` 并重启；从 backend 目录用项目 Python 执行 `python -m app.access create --label 审核人员 --role reviewer --project S1-DEMO`，命令只显示一次访问令牌。网页输入令牌后建立 HttpOnly 会话。其他角色为 viewer、inspector、rectifier、admin；用 `python -m app.access revoke --label 审核人员` 撤销。修改“演示安全员”等显示姓名不会赋予审批权。

本轮没有启用令牌模式或生成操作员令牌；令牌与模型密钥均不应加入交付资料。该模式未接企业 SSO 或正式电子签名，详细边界见外层 `docs/architecture/Agent框架2.0实现说明_20261019.md`。
