## 结论

本轮选定的 1,505 个原件已经全部下载，合计 11,123,030,705 字节（约 11.1 GB / 10.359 GiB）。下载时逐文件比对源 MD5、记录 SHA-256，最终文件与清单核对全部通过，无残留未完成下载。58 个 IFC 均成功读取，227 个 PDF 均可读取，20 个 ZIP/SMC 的成员 CRC 检查通过；1,050 张原始照片和 6 幅正射影像均已建立元数据索引。

S1 可以提供同一真实项目的建筑、结构、机电、场地、施工影像和进度数据，适合作为独立 Web 演示平台的项目底座。已验证原生计划和 4D IFC 的任务关联，以及案例抽样构件回到原始模型的映射。它不直接提供一个已经完成“发现隐患—审批—整改—复核”的安全案例；专项安全施工方案、适用安全规范、现场检查标注、审批及整改复核证据仍需补齐。

首个 Case 建议采用 **2019-06-03 S1 上部结构施工区域的洞口、临边与并行工序风险检查**。时间与真实照片、真实计划一致。方案中的“第五层 MEP”是可选示例，不应套用到现有三期照片上。若必须采用第五层 MEP 场景，须另取得同项目、该施工阶段的现场照片和作业资料。

## 已验证的关联

### 施工计划与 BIM

`Overallplanning Blok S1.pp` 实际为 SQLite 数据库。以只读方式提取出 333 条 TASK、331 条 LINK，并保留 BAR、EXPANDED_TASK、原生任务 ID、时间和层级。数据库完整性检查通过。

`BIM 4D Blok S1_IFC.ifc` 为 IFC2X3，包含 384 个 IfcTask、384 个 IfcScheduleTimeControl、332 条 IfcRelSequence 和 60 条 IfcRelAssignsToProcess。333 条原生 TASK 均能依据“名称、完整层级、计划起止日期”在 4D IFC 中唯一匹配。384 与 333 的差额包含汇总、里程碑和额外可视化任务，不应直接按数量判断数据冲突。

60 条任务—构件关系涉及 16,316 个不同构件，但其中 `ST03390 / Rest` 是包含 9,154 个对象的兜底任务。不能将这些对象视为具有精确工序归属。

已围绕 ST00330、ST00340、ST00390 建立 74 条构件映射，全部得到唯一匹配：建筑构件使用导出属性中的原始 ARCHICAD IFC ID；结构构件使用唯一 Revit Tag 与 IFC 类别组合。4D 重建后的 GUID 与单独结构模型的 GUID 没有直接重合，因此接口必须同时保存模型版本、4D GUID、源 GUID 和映射依据。8 个抽样构件成功生成几何及米制包围盒；这不等于全部模型完成了工程级几何有效性认证。

### 照片与计划时间

原始照片分别来自 2019-05-29、2019-06-03、2019-06-05。已查看的样本是塔吊相机俯视主体施工影像，包含实际拍摄时间、相机编号、GPS 和部分姿态信息。照片不是逐条隐患检查记录，没有现成的构件 GUID、危险源标注或整改前后配对。EXIF 未声明时区，保留原始时间，不能擅自转为 UTC。

影像目录还包含 6 幅带地理参考的正射影像。5 幅使用 EPSG:28992、标称像元边长 0.0161 m；2019-06-05 下午的一幅使用 EPSG:32631、标称像元边长 0.01483 m。不同 CRS 必须分别识别并转换。像元大小不等于定位精度。它们比单张塔吊原图更适合作为“像素—投影坐标—BIM 区域”的关联桥梁，原始照片保留作现场观察证据。

原始计划中：

| 活动 | 计划时间 | 关联判断 |
| --- | --- | --- |
| 三层叠合板施工 ST00340 | 2019-05-22 至 2019-06-03 | 与前两期照片时间相交 |
| 四层墙体及预制构件施工 | 2019-05-29 至 2019-06-12 | 与三期照片时间相交 |
| 四层叠合板施工 ST00390 | 2019-06-05 至 2019-06-14 | 与第三期照片时间相交 |
| 五层主体施工 | 2019-06-13 起 | 不在三期照片的拍摄窗口内 |
| 竖井安装总体任务 | 2019-06-20 起 | 现有照片不能证明该工序正在进行 |

这是计划窗口关联，不是施工实际进度证明；计划中的 ActualStart/ActualFinish 为空时必须显示为“实际状态待确认”。施工层与其上方楼板的 BIM 归属层可能不同，应同时展示活动层级和对象原始楼层，不能简单用同名楼层等同关联。

### 图纸、建模方法与施工方案

建筑、结构、机电图纸可通过项目号、图号、楼层和标高与模型辅助核对。部分图纸为 DWG，数据集中同时提供了大量 PDF；Web 首版优先使用 PDF 与 IFC。ZIP 保留原包并核查成员及 CRC。

版本检查发现：四层建筑平面 UO104 含 2019-12-03 修订，四层通风图 S1-W57-04-INS/OPB 标注 2020-07-23、Revisie，四层地暖图含 2020-05-29 修订。它们可证明同项目、同楼层的设计关联，不能冒充 2019-06-03 现场当时生效的版本。结构四层楼板图 U-0400 的修订至 2019-02-11，并明确引用 2019-01-25 的机电空间预留模型，可作为更早的关联线索；其现场采用状态仍需确认。平台要区分拍摄时间、计划时间、设计版本日期和上传日期。

`BIM KICK-OFF Blok S1.pdf` 是 41 页项目 BIM 协调资料，包含参与方、模型命名、楼层命名、原点及建模协作要求。`Werkmethode modelleren Batch E/W S1.pdf` 是机电建模批次方法，不能当作现场专项安全施工方案。公开目录未提供经审批的临边/洞口防护、主体施工安全方案或 JSA。

### 空间坐标与精度限制

有 4 个 RD 控制点、原始 PRJ、三期网格 offset、LAS 坐标系说明和 BIM 原点资料，可为后续配准提供线索。当前存在必须核对的问题：

- 个别 Revit IFC 的经纬度仍是美国默认位置，与荷兰项目位置不符，不能直接用于照片定位。
- 部分深化模型楼层标高为 0，且包含局部原型/加工对象；应按真实对象变换和组合关系判断空间位置。
- LAS/网格 Y 坐标约为 -353 万，而控制点 Y 约为 38.4 万。原文件使用的 Polar Stereographic 定义与标准 RD New 的 Oblique Stereographic 定义不同，不能只凭坐标系名称直接叠加。坐标诊断结果单独保留；若未完成独立控制点检查，不开放依赖照片定位的距离或碰撞结论。
- 相机姿态信息并不完整，样本中 yaw 为空且 GPS status 为 V。GPS 有值不代表已达到构件定位精度。

配准验收应交付变换参数、控制点来源、拟合残差、独立检查点误差与高度基准。首版可先采用“人工确认照片区域—模型区域”的关联，并在界面明确关联方式及置信状态。

已经用源 LAS 的 WKT 到 EPSG:28992 试算三个网格原点，转换后落在控制点附近，例如 2019-06-03 网格原点约为 RD (160094.914, 384168.789)。这解释了量级差异，验证了可处理的坐标转换路径；尚不代表网格与 BIM 已完成配准，也不证明像素—构件对应精度。投影方法区别可核对 [PROJ 官方说明](https://proj.org/en/stable/operations/projections/sterea.html)。

## 对照完整 Case 的 13 个步骤

| 步骤 | 已有数据与实现输入 | 仍需补齐或验收 |
| --- | --- | --- |
| 1 创建任务 | 项目、真实日期、原生任务 ID、位置候选 | 建立 Case ID、检查范围、操作者及权限 |
| 2 获取 BIM 上下文 | 建筑/结构/机电 IFC、原始 GUID、楼层与构件属性 | 建立统一模型版本、米制坐标、构件/区域索引 |
| 3 获取现场证据 | 三期完整原始影像、EXIF、相机编号 | 选取清晰影像，标注 ROI、位置与可观察对象；VLM 输出带置信度 |
| 4 对齐施工状态 | 原生任务、日期、依赖、4D 构件关系 | 区分计划和实际；确认活动层与楼板归属层关系 |
| 5 统一安全状态 | 可追溯的任务、构件和照片元数据 | 编制一份同区域施工方案/作业任务卡；记录人工确认与不确定性 |
| 6 检索规范 | BIM 协作资料可作为项目知识 | 补适用安全标准、条款版本、适用地域和工序；BIM 协议不充当安全规范 |
| 7 风险判断 | BIM 几何、施工工序与照片候选证据 | 经人工核实的观察标签、风险分级规则及暴露信息 |
| 8 工具校验 | IFC 解析和抽样几何已验证 | 实现洞口尺寸、邻近关系与证据完整性校验；不让 LLM 估算工程尺寸 |
| 9 生成控制方案 | 作业空间、工序和施工资料背景 | 同 Case 控制措施、约束、责任角色与验证要求 |
| 10 形成决策包 | 源文件 ID、版本、任务—构件映射 | Finding、Evidence、Rule、Risk、Control、Owner、Assumptions、Reviewer |
| 11 人工授权 | 数据集没有安全审批记录 | 平台运行时由实际演示操作者审批、修改或拒绝，记录事件 |
| 12 现场实施 | 数据集没有针对该隐患的整改记录 | 提交同一位置/对象的整改证据，或明确标识的受控演示数据 |
| 13 验证与闭环 | 三期历史影像可作时间对比 | 不能认定为整改前后证据；补同点位复核资料，演示通过、退回、重新打开 |

## 补数据的具体做法

1. 先以真实照片时间和计划选择一个工作面，不强行指定第五层 MEP。人工确认 1 个区域与若干真实构件；产出照片 ROI—区域—构件映射表，并标记确认人和依据。
2. 从 1,050 张原始照片中筛选 10–30 张清晰样本，并使用 6 幅正射影像辅助区域定位，覆盖可识别、遮挡、证据不足和正常对照。俯视照片不能稳定证明的 PPE 或隐蔽防护状态，保留“未知”，不补造标签。
3. 补一份与该工作面、日期和工序对应的施工任务卡、施工方法及防护要求。若为案例作者编制，标记 `origin=demo_authored`，由专业人员复核；不冒称 S1 原工程审批文件。
4. 补适用安全知识库。荷兰历史项目事实与中国标准教学演示应分别声明适用前提，不能把中国现行条款直接写成 2019 年荷兰项目的违法结论。
5. 为人工审批、责任分配、实施、复核准备同一 Case 的可控演示流程。可用同 BIM 区域派生的、明确标识为模拟的防护前后场景；若使用真实整改照片，须核实同点位、拍摄时间和整改对象。
6. 制作至少一条“复核失败→退回整改”和一条“条件改变→重新打开”分支；证据不充分时停留在待核实状态，不能自动销项。

## 开发顺序与验收

### 先建立离线数据层

保留原始文件不变，将计划、构件映射、照片元数据、PDF 文本和所有来源版本转成结构化数据。对模型离线预处理，输出按楼层/区域划分的轻量几何及 GUID 映射；浏览器不直接加载数百 MB 的全模型。先完成照片—区域人工确认和坐标问题诊断，再实现需要精确空间输入的工具。

验收：源文件全部校验；333 条任务可查、日期和层级可追溯；抽样映射回原模型一致；3D 点选返回相同 GUID；照片绑定具有明确依据；未通过配准的照片不参与精确空间测距。

### 再完成 Case 与工具接口

建议沿用参考项目的 Vue 3、FastAPI、SQLite 和 LangGraph 技术方向，新增 BIM 解析/三维查看。先用一个项目和一个 Case，避免提前引入多租户、实时传感或复杂服务拆分。专业 Agent 先实现为同一工作流内的职责节点。

最少工具为 BIM Query、Spatial/Geometry Check、Schedule Query、Evidence Query、Rule Retrieval 和 Case/Event Store。每次调用保存输入、结构化输出、耗时、来源和失败原因；所有空间与规则判断由明确工具产生。

### 最后实现 13 步交互闭环

项目/BIM、Safety Case、Agent Workflow、Evidence、Risk & Intervention、Verification 六类页面围绕同一 Case 联动。Coordinator 组织 Knowledge、Inspection、Risk、Intervention、Verification 职责节点，显示真实调用及证据，不用固定动画冒充执行。

验收：用户提交问题后，13 步有对应数据和事件；点击风险可定位构件并回到原始照片/条款；人工审批后才能进入实施；复核必须检查新证据及剩余风险；失败退回或条件变化可重新打开。真实来源、人工关联、作者编制和模拟证据在每条记录上明确区分。

## 文件交接

- `data/external/s1/raw/`：按来源类别与上游文件夹保存原件，保留三期和三相机目录，避免同名网格相互覆盖。
- `data/external/s1/prepared/`：计划、任务依赖、任务/构件映射、影像元数据、格式检查和 Case 种子数据。
- `data/external/s1/audit/`：原始检查输出、PDF 文本、照片联系表和坐标检查依据。
- `scripts/s1_dataset.py`：公开目录读取、断点续传、源大小/MD5 比对、SHA-256 留存；不保存临时访问令牌或临时下载凭据。
- `scripts/prepare_s1_case.py`：模型映射和几何抽查、原生计划只读提取、照片/PDF/压缩包检查。
- `scripts/verify_s1_downloads.py`：将下载凭据清单与完整来源清单、本地文件重新核对，导出最终 JSON/CSV 清单。分析依赖固定在 `scripts/requirements-data.txt`。

数据集说明总体采用 CC BY 4.0；文件自身的许可声明仍须保留，例如 BIM-ILS 文档内标注了 CC BY-ND 4.0。平台中保留项目、作者和原始来源信息。

本轮完成数据准备与可用性审计，不包含 Web 业务页面开发或缺失安全资料的伪造。
