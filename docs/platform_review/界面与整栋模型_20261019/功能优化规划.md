## 当前真正缺少的能力

1. **检查范围还不够直观**：表单选择“边线 1 / 2”，用户看不出是哪条边；人员点主要通过参数表达。
2. **施工状态仍较单一**：当前是一项活动的有效时间窗，尚未演示多个工种同时占用空间、冲突及调整施工顺序。
3. **证据与 BIM 分散**：照片、风险、BIM 多通过页面跳转串联，操作时需要记住关联；Safety State 也以折叠信息为主。
4. **工程空间关系仍有限**：已实现选中构件几何、标注人员到边线距离和邻近包围盒候选；尚未建立完整洞口、通道、设备与临时设施的空间关系。
5. **措施执行粒度较粗**：已有批准版本、责任人和复核；还未形成每项措施各自的负责人、期限、实施证据与验收记录。

## 下一阶段建议与验收

| 优先级 | 功能 | 用户实际看到的变化 | 依据与最小实现 | 验收 |
|---|---|---|---|---|
| 必要 P1 | 范围选择与几何标注 | 点楼层 → 点区域 → 点边线；当前边线高亮，人员点及距边线距离同时显示 | 继续使用真实 IfcSlab 网格；顶面候选边线由程序取得，临空属性由人工确认。人员点标注带来源 | 切换边线时三维高亮与工具输入一致；移动人员点后距离可重复计算；换 GUID 不沿用上一构件的边线 |
| 必要 P1 | 同一 Case 联动工作台 | 左侧范围/任务，中央 BIM，右侧风险/照片；点风险定位构件与证据，底部查看 Agent 记录 | 复用现有 Case、证据、规则与运行接口，保存一个当前选中 Finding；Safety State 显示活动、位置、时间、观察和缺失项 | 点一条风险时 GUID、照片、时间、条款全部对应；模型候选和人工确认值可以对照 |
| 必要 P2 | 多活动时间与空间检查 | 用时间轴查看“机电材料转运 + 相邻工种作业”，显示冲突区域和各自责任主体 | 同一案例补编两项可控活动，保存 task_id、区域多边形/空间体、起止时间、责任主体；程序先判断时间交集，再计算空间交叠或距离 | 同空间不同时间不报同时作业冲突；同时间不同空间不误报；同时同地触发冲突；调整时序后重新验证 |
| 必要 P2 | 现场文本融入 Safety State | 可录入巡检记录、班前交底或异常描述；结论可追溯到原文段落 | 文本保存来源、时间、区域、版本；DeepSeek 提取候选事实，冲突和缺失项要求澄清 | 照片与文字矛盾时保留两方依据；不能自动用较新文本覆盖人工确认值 |
| 可选 P3 | 措施执行清单 | 一条风险下有多项措施，各有责任人、期限、状态和验收证据 | 在现有控制版本上增加 action item；人工批准后锁定验收要求 | 只完成部分措施不能整案关闭；修改验收要求后需新审批；每项记录可导出 |
| 可选 P3 | 规范条件和历史案例检索 | 能说明适用工序、前提条件和例外；引用来源可展开 | 先扩充已核对条款和少量历史案例，再评估检索；保留标准、条款、日期和版本 | 固定问题集核查召回与引用；历史条款不参与当前判定，缺少适用条件时要求补充 |

推荐开发顺序：先完成 P1 的“范围可视化 + 同案联动”，再用两项可控施工活动打通 P2 的时空冲突、措施调整与重新验证。这样可以直接补足原方案 Step 2、4、5、7、8、9，而无需另起平台。

## 数据准备

- 保留原 IFC 和每个局部检查对象的 GUID；整栋 GLB 用于快速浏览，空间计算仍读取构件网格与实际坐标。
- 公开计划包含 task-product 关系，但现有审计显示某一结构设计模型与计划模型的 GUID 交集为 0，不能直接把该结果当作当前建筑已完成匹配。为演示补编同区域的两项活动，并逐条记录人工映射及来源。
- 为新任务准备范围、时段、人员/设备点与 3–5 组可控状态。原始照片可继续使用公开 S1 图像，跨资料来源的关联仍明确标注。
- 每个新增风险类型同时准备正常、触发、资料不足、复核失败四种输入；界面效果与确定性工具结果共同验收。
