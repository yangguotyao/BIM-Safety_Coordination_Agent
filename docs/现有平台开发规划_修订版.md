# 现有平台开发规划 修订版

规划日期：2026年10月18日。状态：仅规划，未实施。本文件是当前开发范围依据，覆盖此前架构路线及平台评估中的实施优先级；历史评估结果保留。

## 目标与范围调整

以组内已开发的BIM-Safety-Coordination-Agent为基础，继续使用Vue 3、FastAPI、LangGraph、SQLite、IfcOpenShell和Three.js。围绕现有L05区域及预置Case完善一条可解释、可交互、可审批复核的Agent展示流程。

本轮规划作以下调整：

- “重开后仍采用旧证据”按用户要求移出开发范围，不安排修改及对应修复验收。重开沿用现有实现。
- 施工方案降为可选的项目知识或文本来源，不建设施工方案编制、审查、版本管理等独立功能。已补编资料保留作参考。
- 保留现有Case、预提取网格、规范库、业务接口和事件日志，不先迁移到另一个区域或另建一套应用。
- 首批集中于Agent的实际参与、上下文、工具与决策包，随后精修界面。单机演示采用现有业务持久化；复杂运行恢复和长期记忆放到后续评估。

## 原方案的要求如何理解

重新核对根目录的BIM-Safety_Coordination_Agent_方案.docx：

- “安全规范与项目知识库”资料清单包含“企业安全管理制度、检查清单、JSA/JHA、专项施工方案”。
- “现场文本资料”清单包含“施工方案、技术交底、作业许可和人员/设备信息”。
- “推荐的最小可运行版本（MVP）”列出IFC、一个区域及安全任务、规范知识库、图像样例、BIM/几何/RAG工具、Agent职责、Case数据库及Web展示，没有单列施工方案审查功能。

因此，施工方案属于可采用的输入资料，并不自动意味着要开发一套方案审查业务。此前将其列为重点开发项超出了本轮所需范围。

第9步的“生成控制方案”仍是核心功能：针对已识别风险提出防护、隔离、通道或作业顺序等控制措施。它是本次安全分析的输出，不要求编制完整的专项施工方案文件。

## 保留现有实现

保留三维查看与GUID定位、区域网格缓存、现有中文FTS5检索、有效条款筛选、Case状态机、人工审核实施复核、数据库事件、工具trace及12项验收入口。既有轮询方式可继续使用，不将改为SSE作为本轮目标。

六项职责继续按原方案呈现：Coordinator、Knowledge、Inspection、Risk、Intervention和Verification。BIM与进度主要作为工具服务。模块可继续保留在现有文件中，按改动需要局部调整，不为目录形式拆出大量空Agent文件。

## 第一批 Agent 核心完善

| 开发内容 | 规划行为 | 验收方式 |
| --- | --- | --- |
| 任务理解 | 接受自然语言检查请求，解析区域、时间、检查重点和已有证据；范围超出当前数据时明确提示 | “全面检查该区临边”和“只检查栏杆高度”形成不同检查重点，不能只改变案例标题 |
| 统一任务上下文 | 将当前Case、BIM摘要、活动、观察、来源及缺失项组织为可校验的Safety State | 每个判断能追到本次使用的构件、活动、证据或规则 |
| 受限工具选择 | Coordinator在现有BIM、进度、证据、检索和检查工具中选择必要调用；设置调用次数和范围限制 | trace显示实际选择、参数与结果，未知工具及越界参数不能执行 |
| 面向任务的规范检索 | 根据任务重点和观察形成查询，继续使用现有FTS5及版本过滤 | 不同重点产生相应检索输入，返回条款及来源，不新增大型知识平台 |
| 风险与控制措施 | 模型综合工具结果形成风险说明和结构化候选措施，明确依据、责任主体、假设和验证要求 | 数值与工具结果一致，候选措施仍需人工批准，不直接写成已实施 |
| 决策包 | 整理Finding、Evidence、Governing Rule、Risk、Control、Owner、Assumptions、Reviewer | 页面和导出均能查看这组信息，来源可回查 |

实际模型参与任务解析、允许范围内的工具选择、证据综合和措施组织。几何、时间和数值判定继续由确定性工具完成，权限与状态检查继续由业务服务执行。

不要求六个职责都分别调用大模型。同类信息可以在一次结构化模型调用中处理；调用次数及上下文长度以演示延迟和部署资源为约束。保留明确标识的固定回放模式，真实模型模式失败时给出错误，不静默展示预置答案。

## 第二批 轻量记忆与工具衔接

### 必要的记忆

| 记忆类型 | 本轮安排 |
| --- | --- |
| 当前任务状态 | 复用Case数据库和分析运行记录，保存任务范围、检查重点、结果引用及待办 |
| 简短对话上下文 | 保存同一Case的近期澄清和简要摘要，支持“继续检查该区域的栏杆”等跟进请求 |
| 业务过程 | 沿用现有审批、实施、复核和事件历史 |
| 历史案例相似检索与用户画像 | 暂缓，首版不建立长期向量记忆服务 |

上下文按当前Case及操作者范围筛选，只加入相关摘要、观察和条款片段；不把全部IFC、图片文件和全部历史装入提示词。图像与模型文件继续用ID和路径引用。

单次分析中断后允许明确失败并重新发起，保留已有业务记录。持久化checkpoint及复杂断点恢复在确有演示需要时再安排，不作为首批完成条件；人工审批等待仍可由现有数据库状态表达。

### 工具与验证

在已有工具外补充必要的输入输出校验、状态、来源、版本、单位及错误信息，不重写已能工作的几何和检索能力。内部Python函数即可，不引入MCP或分布式Agent通信作为前置依赖。

“修改措施后复核仍使用旧标准”保留在开发范围内：

- 对现有支持的防护存在、栏杆高度、固定和连续性等检查项建立明确参数。
- 审核修改这些参数后，复核读取所批准措施版本的对应要求。
- 对超出现有检查能力的文字要求，明确列为人工核验项，不能声称固定清单已自动验证。
- 验收样例：演示项目要求提高到1.50m时，1.20m证据不能自动判为满足该要求。该数字仅是自定测试参数。

这部分围绕现有Case补齐控制与验收的关联，不建设通用规则语言或任意工程计算平台。

## 第三批 页面与演示体验

保留现有深蓝和青绿风格及主要页面，只围绕演示任务优化：

1. 提高小字与次级文字可读性，减少同时展示的英文标签和技术编号。
2. 案例详情突出当前风险、关键依据、待办及下一步操作。
3. 展示本次任务理解、实际工具调用、结果和控制措施；已有trace继续复用。
4. 改善BIM默认视角、亮度、区域定位及风险选择反馈。
5. 在现有证据、措施、实施和复核之间提供更直接的跳转与对照。

不新增施工方案审查页面、完整进度计划软件或企业级账号管理。责任主体先沿用现有演示角色，确保决策包和人工操作记录可见。

## 对应13步的展示主线

| 原方案步骤 | 本轮安排 |
| --- | --- |
| 1 创建任务 | 补自然语言任务理解及明确的检查重点 |
| 2 BIM上下文 | 复用现有查询、区域网格和GUID定位 |
| 3 现场证据 | 复用现有演示观察，清楚标识其来源和模拟状态 |
| 4 施工状态 | 复用模拟任务窗口，明确活动、区域、构件及时间关系 |
| 5 语义理解 | 增加统一Safety State及模型综合 |
| 6 规范检索 | 由当前任务和观察驱动检索，保留来源版本 |
| 7 风险判断 | 综合工具结果形成有依据、有不确定性说明的候选 |
| 8 工具校验 | 复用确定性检查并呈现输入、输出和适用范围 |
| 9 控制方案 | 生成受约束的候选控制措施 |
| 10 决策包 | 明确关联证据、依据、责任与复核要求 |
| 11 人工授权 | 复用现有批准、修改和拒绝流程 |
| 12 实施 | 复用现有实施与证据记录 |
| 13 验证闭环 | 对支持的检查项绑定批准要求；重开沿用现有实现 |

真实照片的VLM识别可单列为后续增强，若首版继续使用标注观察，应明确为演示输入，不能表述为已完成视觉模型识别。已有S1原件与补编资料均保留，按需要选取，不将全量导入设为本次任务。

## 开发顺序与本轮交付

开发时按“任务理解与Safety State → 受限工具调用及检索 → 风险和控制决策包 → 轻量上下文 → 措施验收关联 → 页面精修”推进。每项完成后复用现有验收，并增加对应的任务解析、参数范围、上下文连续性及措施参数变化检查。

本轮只确定上述范围和验收标准，不创建应用模块、不修改接口、不执行修复、不改数据库、不发布网站。后续实现以本规划为准，避免沿用旧评估中的扩大范围。
